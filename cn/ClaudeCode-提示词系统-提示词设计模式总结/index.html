提示词设计模式总结

Posted by zhangqinzhong on 2026-06-28
Estimated Reading Time 7 Minutes
Words 1.8k In Total
Viewed Times

从 Claude Code 源码提炼的 12 个可复用提示词设计决策。这些模式不是教条，而是经过真实工程验证的设计选择，每一条背后都有具体的问题要解决。

模式 1：双重约束

问题： 单一规则容易被遗漏。
解法： 在系统层和工具层分别重申同一规则，形成两道防线。

示例： "不要用 bash 替代专用工具"出现在两处：

  • 系统提示词的 getUsingYourToolsSection()
  • BashTool 的 getSimplePrompt() 开头

适用场景： 任何"默认行为很强、需要持续纠偏"的规则。

模式 2：条件注入（feature flag 门控）

问题： 功能开关影响提示词内容，但不能让 prompt 变成一堆 if-else。
解法： 用 feature() 函数在拼装阶段条件性地包含/排除文本块。

示例：

关键： 死代码在打包时被 DCE 完全消除，外部版本的用户永远看不到内部功能的提示词。

模式 3：静态/动态分割（Cache 边界）

问题： 动态内容（用户目录、git status）会破坏全局 Prompt Cache。
解法： 用明确的边界标记分割提示词，静态内容全局缓存，动态内容会话缓存。

效果： 静态层约 4000 token，缓存命中后成本降 90%。

模式 4：路径归一化（跨用户缓存）

问题： 每个用户的临时目录路径不同（/tmp/claude-1001/ vs /tmp/claude-1002/），导致全局缓存失效。
解法： 写入提示词前将实际路径替换为通用变量。

推广： 任何包含用户特定数据的路径，写入提示词前都应归一化。

模式 5：实时配置 JSON 注入

问题： 沙箱权限是运行时计算的，不能写死在提示词里。
解法： 将运行时配置序列化为 JSON，直接插入提示词。

效果： Claude 能"读懂"当前的沙箱限制，遇到权限错误时能判断是否是沙箱导致的。

模式 6：动态 Agent 列表 → 消息附件

问题： Agent 列表是动态的（MCP 工具变化），每次变化都让工具 schema 缓存失效，约浪费 10% 的 cache_creation token。
解法： 把 Agent 列表从工具描述中移出，改为每轮的消息附件（agent_listing_delta）。

推广： 任何高频变化的动态列表，都可以用消息附件代替内嵌在工具描述里。

模式 7：角色反转提问（Socratic）

问题： 用户想测试自己的方案，但 AI 默认给答案而不是提问。
解法： 提示词声明 AI 是"提问者"而不是"回答者"。

关键： "提供你的推荐答案"这一条让提问变成协作而非审讯。

模式 8：两轮读写策略

问题： 需要读取 N 个文件再写入 N 个文件时，朴素做法会产生 2N 轮（Read A → Write A → Read B → Write B）。
解法： 提示词明确规定并行两轮策略。

效果： 对于处理 N 个文件，从 2N 轮降到 2 轮（固定成本）。

模式 9：版本感知语法指导

问题： 同一工具有多个版本，语法不兼容（PowerShell 5.1 vs 7+）。
解法： 运行时检测版本，动态注入版本特定的语法说明。

适用场景： 任何有版本分歧的环境（Node 版本、Python 2/3、bash/zsh 等）。

模式 10：工具替代优先级声明

问题： 提供了专用工具但 AI 倾向于用通用工具（Bash）替代。
解法： 在工具描述里明确"如果有 X，优先用 X 而不是我"。

关键： 用 ALWAYS/NEVER 的强语气，因为这是习惯性行为，弱措辞不够有效。

模式 11：强制来源引用

问题： AI 给出信息时用户无法验证真实性。
解法： 提示词强制要求在每次响应末尾附上来源列表。

MANDATORY 的必要性： 弱措辞（“建议包含来源”）在实践中经常被跳过。重要约束需要强语气。

模式 12：倒金字塔 + 沉默原则

问题： AI 输出冗长，把重要信息埋在中间。
解法： 提示词明确说明信息密度原则和"何时沉默"。

推广： 给出具体的字数/格式约束，比"保持简洁"有效得多。

模式对照表

模式 解决的核心问题 关键技术
双重约束 规则遗漏 多层重申
条件注入 功能差异化 feature() DCE
静动分割 Cache 失效 BOUNDARY 标记
路径归一化 用户差异破坏缓存 变量替换
实时 JSON 注入 运行时配置感知 序列化注入
动态列表附件化 工具 schema 频繁失效 消息 attachment
角色反转 默认给答案 提问者声明
两轮读写 顺序读写效率低 明确并行策略
版本感知 多版本语法冲突 运行时检测注入
工具替代优先级 通用工具替代专用工具 ALWAYS/NEVER
强制来源引用 信息可验证性 MANDATORY 强语气
