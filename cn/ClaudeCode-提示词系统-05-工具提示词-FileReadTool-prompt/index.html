概述

FileReadTool（工具名 Read）的提示词描述了文件读取的能力边界和使用规则，包括支持的文件格式（图片、PDF、Jupyter notebook）、行号格式、读取范围限制等。

逐段解读

乐观读取

这段话解决了一个常见的过度谨慎问题：Claude 有时会在读文件之前先用 BashTool 检查文件是否存在（多一次工具调用）。这里明确告知：直接读，不存在会有错误信息，无需预先检查。

只读，不读目录

明确边界：目录读取用 bash ls，文件读取用 Read。防止 Claude 用 Read 尝试读取目录。

行号格式

这条说明与 FileEditTool 深度耦合。FileEdit 要求 old_string 必须与 Read 工具的输出格式精确匹配。知道是 cat -n 格式，Claude 在编辑时才能正确处理行号前缀的剥离。

多格式支持

格式 处理方式
文本文件 返回带行号的文本
图片（PNG/JPG/etc） 以图像内容块返回，视觉呈现
PDF 转换为文本，支持页码范围
Jupyter .ipynb 解析所有 cells 及输出

截图读取

这是一个经验性规则：用户经常提供截图路径（/tmp/screenshot.png），Claude 应该直接用 Read 工具查看，而不是用其他方式。

加载逻辑

  • 来源文件：tools/FileReadTool/prompt.ts · renderPromptTemplate()
  • 动态部分：
    • PDF 说明：isPDFSupported() 为 true 时才包含
    • maxSizeInstruction：根据配置的最大文件大小动态生成
    • offsetInstruction：根据是否有 offset/limit 参数选择默认或精确读取说明
  • 缓存：大部分内容可以缓存，PDF 说明根据平台能力决定是否包含

特殊机制：FILE_UNCHANGED_STUB

当 Claude 试图重复读取同一文件（且文件内容未变化）时，系统返回这个 stub 而不是完整内容。节省 token，防止上下文膨胀。

readFileState（FileStateCache）追踪每个文件的最后读取时间戳，如果文件修改时间未变，就返回这个提示而非重新读取。

依赖关系与互动

  • 与 FileEditTool 深度耦合：FileEdit 的 old_string 必须与 Read 返回的内容格式完全匹配。FileEdit 的提示词中也明确说明了这一点（“preserve the exact indentation as it appears AFTER the line number prefix”）
  • 与 BashTool 互动：系统规则和 BashTool prompt 都指向"读文件用 Read 而不是 cat"；这里的描述是工具自己对这个规则的补充说明
  • 与 readFileState 缓存互动：FILE_UNCHANGED_STUB 机制依赖 ToolUseContext.readFileState，这个缓存也被 FileEditTool 用来追踪文件修改状态
  • 与图片/多媒体支持互动：Read 工具的图片支持依赖 Claude 的多模态能力，提示词明确告知 Claude 这个能力是可用的
