核心概念词汇表

Posted by zhangqinzhong on 2026-06-28
Estimated Reading Time 7 Minutes
Words 1.9k In Total
Viewed Times

理解 Claude Code 源码的必备概念，按依赖顺序排列。

Tool（工具）

定义： Claude 能调用的原子能力单元。每个 Tool 是一个实现了固定接口的对象。

工具是 Claude Code 中”最小功能单元”。Claude 只能通过工具来影响外部世界——读文件、写文件、运行命令都必须通过对应工具。

call()（工具执行函数）

定义： 每个工具必须实现的核心方法，是工具真正干活的地方。

call() 有两个主要参数：

第一个参数 args：Claude 传来的输入

Claude 在调用工具时，会在 tool_use block 里附带一个 input 字段。这个字段经过 inputSchema（Zod）验证后，就是 call() 的第一个参数。

args 的结构完全由 inputSchema 定义——Claude 只能传 Schema 里声明的字段，CC 用 Zod 验证后再交给 call()。

第二个参数 context：CC 注入的运行环境（见 ToolUseContext）

和 args 不同，context 跟 Claude 无关，是 CC 自己构造并注入的。工具通过它访问文件缓存、UI 状态、中止信号等运行时能力。

ToolUseContext（工具执行上下文）

定义： 工具执行时能访问的”运行时环境”，通过 call() 的第二个参数传入。

核心字段：

设计意图： 把工具执行所需的一切打包成一个对象，工具实现无需 import 任何全局状态，只需依赖这个对象。这让工具在主线程和子 Agent 中都能正确运行。

ToolResult（工具返回值）

定义： 工具 call() 的返回类型。

contextModifier 是高级用法：某些工具（如 EnterPlanModeTool）执行后需要改变后续所有工具的权限模式，通过这个字段实现。

PermissionResult（权限结果）

定义： checkPermissions() 的返回值，决定工具是否能执行。

检查顺序：

  1. validateInput() — 静态校验（参数格式、语义合法性）
  2. checkPermissions() — 工具自定义逻辑
  3. 权限系统（hooks/toolPermission/）— 对照 allow/deny 规则

PermissionMode（权限模式）

定义： 全局的权限策略，决定默认如何处理工具调用请求。

模式 行为
default 只读操作自动允许，写操作弹窗确认
auto 大部分操作自动允许（YOLO 分类器辅助判断）
plan 所有写操作被阻止，只允许读和规划
bypassPermissions 跳过所有权限检查（危险，需要明确授权）
acceptEdits 文件编辑自动接受，其他操作弹窗

Message（消息）

定义： 对话历史中的一条记录，比 Claude API 的消息类型更丰富。

主要类型：

normalizeMessagesForAPI() 在发送 API 请求前，把内部消息格式转换成 Claude API 接受的格式，并过滤掉 SystemMessage 等内部专用消息。

SystemPrompt（系统提示词）

定义： 类型别名 type SystemPrompt = string[]，即一个字符串数组。

每个字符串是一个独立的”块”，最终用 \n\n 拼接后发给 API。设计成数组而不是单个字符串，是为了方便分块构建和 Prompt Cache 的分段缓存。

Feature Flag（功能标志）

定义： 控制功能开关的机制，通过 feature('FLAG_NAME') 调用。

常见 flag：

Flag 功能
MONITOR_TOOL Monitor 工具（流式监控）
KAIROS 自主模式（proactive agent）
COORDINATOR_MODE 多 Agent 协调器
BRIDGE_MODE IDE 桥接模式
VERIFICATION_AGENT 自动验证 Agent
EXPERIMENTAL_SKILL_SEARCH Skill 搜索功能

AppState（应用状态）

定义： 整个 REPL 界面的状态树，存储在 React Context 中。

关键字段：

setAppState 被注入到 ToolUseContext 中，工具执行时可以直接更新 UI 状态。

Compaction（上下文压缩）

定义： 当对话历史接近模型上下文上限时，自动压缩早期消息以腾出空间。

三种压缩机制：

类型 触发时机 做什么
autoCompact Token 数超过阈值 调用 Claude 总结历史，替换为摘要
microCompact 轻量压缩 把工具结果替换为简短摘要标记
cachedMicroCompact 带缓存的微压缩 复用之前的摘要，节省 API 调用

MCP（Model Context Protocol）

定义： Anthropic 开放的标准协议，让外部程序以标准方式向 Claude 暴露工具和资源。

Claude Code 作为 MCP 客户端，可以连接任意 MCP 服务器，动态获取新工具。连接的服务器工具会自动合并进工具列表，对 Claude 透明可用。

Skill（技能）

定义： 用户可调用的可复用工作流，以 /skill-name 形式触发。

Skill 本质上是一段 Markdown 文档，包含 name、description 和具体指令。当用户键入 /commit 时，SkillTool 读取对应 Skill 文件，把其中的指令展开注入到对话中。

Hook（钩子）

定义： 用户在 settings.json 中配置的 shell 命令，在工具调用前后自动执行。

Hook 的反馈（stdout）被当作”用户消息”处理——Claude 会读取并响应 hook 输出的内容。
