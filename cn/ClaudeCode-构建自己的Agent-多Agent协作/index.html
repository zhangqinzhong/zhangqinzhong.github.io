什么时候需要多个 Agent

单个 Agent 的局限：

  • 上下文容量：一个 200K context 的 Agent 无法处理大型代码库的全面重构
  • 并行能力：顺序执行多个独立子任务，速度受限
  • 专业分工：同一个 Agent 做审查、修改、测试，容易自我说服

多 Agent 解决这三个问题：让多个专业化 Agent 并行工作，由一个协调者 Agent 统一调度。

CC 的多 Agent 方案：AgentTool

子 Agent 有独立的：

  • 工具权限集（可以限制子 Agent 只能读，不能写）
  • 上下文（不共享主 Agent 的历史）
  • token budget（防止子 Agent 消耗过多资源）
