概述

根据当前会话的具体条件（启用了哪些工具、是否有 Skill、是否开启验证 Agent 等）动态生成的引导内容。每个会话的配置不同，这部分内容也不同。

各条目说明

AskUserQuestion — 权限被拒时的处理

仅当 AskUserQuestionTool 在工具列表中时才包含这条。
配合系统规则中"工具被拒不能重试"的规定，提供了一个合理的升级路径：不能重试 → 可以询问原因。

! 前缀命令建议

仅在非交互式会话中跳过（getIsNonInteractiveSession() 返回 false 时生效）。
! 前缀是 Claude Code REPL 的特殊语法，允许用户在提示符里直接运行 shell 命令并把输出注入对话。常用场景：需要用户手动登录的交互式认证（gcloud auth login、aws configure 等）。

AgentTool 使用指引

标准版：

Fork 版（isForkSubagentEnabled() 为 true 时）：

Fork 模式是更高级的子 Agent 机制，子 Agent 的工具输出不会污染主线程上下文。

Skill 调用说明

仅当 SkillTool 在工具列表中且有可用的 Skill 命令时才包含。
这条规则明确了：/xxx 格式是用户的简写，Claude 收到后应该通过 SkillTool 展开执行，而不是自己解释这个命令。

验证 Agent（Verification Agent）

仅当：

  1. hasAgentTool（工具列表中有 AgentTool）
  2. feature('VERIFICATION_AGENT') 为 true
  3. GrowthBook flag tengu_hive_evidence 为 true（A/B 测试中）

这是一个复杂的验证约束：对于非平凡的实现（3+ 个文件修改、API 变更等），Claude 必须在报告完成之前启动一个对抗性验证子 Agent，由验证 Agent 独立确认实现是否正确。

加载逻辑

  • 位置：动态层第一个 section（SYSTEM_PROMPT_DYNAMIC_BOUNDARY 之后）
  • 缓存：会话缓存（工具列表在会话期间通常稳定）
  • 条件：完全基于当前工具列表和 feature flag 动态生成

依赖关系与互动

  • 与 AgentTool 互动：AgentTool 的高层使用策略在这里声明，AgentTool 自己的 prompt 里有具体的调用格式
  • 与 SkillTool 互动：用户输入的 /xxx 命令需要 Claude 知道要通过 SkillTool 处理，这条规则建立了这个连接
  • 与权限系统互动：AskUserQuestion 建议是权限被拒流程的组成部分
  • 与 Prompt Cache 互动：这个 section 的内容取决于工具列表，工具列表在 MCP 服务器连接/断开时可能变化，因此不适合全局缓存，放在动态层
