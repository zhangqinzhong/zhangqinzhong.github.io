权限模式

Posted by zhangqinzhong on 2026-06-28
Estimated Reading Time 3 Minutes
Words 848 In Total
Viewed Times

概述

Claude Code 的权限系统控制 Claude 执行工具时是否需要用户确认。不同的权限模式决定了默认的自动化程度，从”每次都问”到”完全自动”都有对应的模式。

五种权限模式

default（默认）

最平衡的模式。isReadOnly() 返回 true 的工具调用自动放行，写操作需要用户确认。日常使用的标准模式。

auto（自动模式）

通过机器学习分类器（”YOLO 分类器”）自动判断工具调用是否安全。用户明确表示信任 Claude 时使用，减少打断。

plan（规划模式）

EnterPlanModeTool 会切换到这个模式。在这个模式下 Claude 只能探索代码库，无法修改任何内容，直到用户批准规划并用 ExitPlanModeTool 退出。

acceptEdits（接受编辑）

当用户明确希望 Claude 自动完成文件修改，但其他操作（如运行命令、git 操作）还需要确认时使用。

bypassPermissions（绕过权限）

最危险的模式，完全信任 Claude。通常用于无人值守的自动化场景或明确知道风险的情况。使用此模式前需要明确授权。

每次工具调用前，按以下顺序检查：

权限规则（Allow/Deny/Ask）

用户可以在 settings.json 中配置规则：

规则匹配语法：

  • 工具名(参数模式) — 匹配特定参数的工具调用
  • * 通配符 — 匹配任意内容
  • 前缀匹配 — Bash(git *) 匹配所有以 git 开头的 bash 命令

规则来源有多个（按优先级）：

  1. 项目 .claude/settings.json（最高优先级）
  2. 用户全局 ~/.claude/settings.json
  3. 企业 MDM 策略

YOLO 分类器（auto 模式）

YOLO 分类器用一个小模型来判断工具调用是否安全，基于：

  • 工具类型和输入参数
  • CLAUDE.md 中的权限相关说明
  • 历史的允许/拒绝决策

ToolPermissionContext

DeepImmutable 确保工具执行时不能意外修改权限上下文，权限只能通过 ToolResult.contextModifier 正式更新。
