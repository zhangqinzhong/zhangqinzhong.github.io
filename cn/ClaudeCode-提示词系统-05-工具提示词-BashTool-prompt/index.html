概述

BashTool 的提示词是所有工具中最复杂的，共 369 行，动态拼装。除了基础的命令执行说明外，还包含：工具偏好引导、多命令并行规则、git 安全协议、完整的 commit & PR 创建 SOP、以及沙箱模式的实时配置注入。

各部分解读

工具偏好引导

这是与系统层"工具使用规范"的呼应，但更具体：直接列出了禁止通过 BashTool 替代的命令，以及对应的专用工具。双重约束确保 Claude 不会遗漏这条规则。

核心执行规则

  • 工作目录持久化：cd 的效果在命令之间保持（同一 session 内的 shell 状态共享）
  • Shell 状态不持久化：环境变量、别名等不跨命令保持
  • 绝对路径优先：尽量用绝对路径，避免 cd 导致的目录混乱
  • 引号路径：包含空格的路径必须加双引号

sleep 命令限制

这部分与 Monitor 工具联动（feature('MONITOR_TOOL') 启用时）：

无 Monitor 工具时：允许短暂 sleep（1-5 秒），但禁止 sleep 轮询。

沙箱配置注入（动态）

沙箱配置被实时序列化为 JSON 注入提示词，让 Claude 知道具体的文件系统和网络限制。这样 Claude 在遇到权限问题时，能判断是沙箱限制还是其他原因。

git commit SOP（完整版）

HEREDOC 格式强制要求：

使用 HEREDOC 而不是直接 -m "..." 是为了正确处理多行 commit message 的格式。

应用场景

BashTool prompt 在以下场景发挥关键作用：

  • 并行命令：Claude 在读取多个相互独立的文件时，会同时发起多个 Bash 调用
  • git 操作：创建 commit 时 Claude 会严格按照 4 步 SOP 执行，包括并行跑 status/diff/log
  • 沙箱感知：遇到权限错误时，Claude 会对照沙箱配置判断是否是沙箱限制导致的
  • 背景任务：长时间命令使用 run_in_background，不用 sleep 等待

加载逻辑

  • 来源文件：tools/BashTool/prompt.ts · getSimplePrompt()
  • 调用时机：BashTool.prompt() → 作为工具 description 传给 API
  • 动态部分：
    • 沙箱配置：每次都重新序列化当前沙箱状态
    • git 指令：根据 USER_TYPE（ant/外部）输出不同版本
    • Monitor 相关条目：根据 feature('MONITOR_TOOL') 条件加载
    • 嵌入式搜索工具环境：省略 Glob/Grep 相关引导

依赖关系与互动

  • 与系统层"工具使用规范"互动：两个层面都有"不要用 bash 替代专用工具"的规定，形成双重约束
  • 与 Monitor 工具互动：sleep 限制规则根据 Monitor 工具是否可用而变化
  • 与沙箱系统互动：SandboxManager 提供实时配置，prompt 把它序列化后注入，Claude 据此调整命令
  • 与 git 安全规则互动（系统层）：操作安全规则定义了"force push 等操作需要确认"，BashTool prompt 细化了 git 操作的具体 SOP
  • 与 _simulatedSedEdit 机制互动：权限弹窗里的 sed 预览功能通过一个内部字段 _simulatedSedEdit 传递，BashTool 检测到这个字段时直接应用预览内容，而不重新执行 sed
  • 与 undercover 模式互动：Anthropic 内部用户在 undercover 模式下，git commit SOP 中不包含模型 ID，防止内部代号出现在公开 commit 里
