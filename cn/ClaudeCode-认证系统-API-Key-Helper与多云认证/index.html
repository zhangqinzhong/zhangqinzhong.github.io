概述

src/utils/auth.ts（2002 行）实现了 CC 的完整认证栈，支持六种认证来源、三大云厂商、外部密钥提供者和企业托管认证。本文档重点覆盖普通 OAuth 文档未涉及的部分：API Key Helper、AWS/GCP 多云认证、认证优先级链。

认证优先级（从高到低）

例外： 托管 OAuth 上下文（CCR / Claude Desktop）忽略所有本地配置，只接受 env/FD 注入的 Token，防止跨会话凭证污染。

API Key Helper

什么是 apiKeyHelper

一个由用户配置的外部命令，CC 调用它来动态获取 API Key。适用场景：

  • 企业密钥保险库（HashiCorp Vault、AWS Secrets Manager）
  • SSO 集成（通过脚本换取临时 API Key）
  • 避免在本地存储明文密钥

配置方式

helper 命令的要求：

  • 执行后通过 stdout 输出 API Key（纯文本，自动 trim）
  • 非零 exit code 或空输出视为失败
  • 超时：10 分钟

缓存策略（SWR）

为什么用 SWR（Stale-While-Revalidate）：
对话中途 Token 过期时，不能阻塞当前 API 调用等待 helper 执行。SWR 保证调用不中断，同时在后台静默刷新。

并发去重：
多个并发请求共享同一个 Promise，不会同时启动多个 helper 进程。

安全约束

  • 如果 apiKeyHelper 来自项目或本地 settings，需用户已信任该工作区（checkHasTrustDialogAccepted()）
  • 非交互式会话（CI/管道）跳过信任检查
  • helper 失败时，CC 不会静默降级到 OAuth，而是报错（防止意外使用个人 OAuth）

GCP 认证

gcpAuthRefresh 配置

与 AWS 的 awsAuthRefresh 机制相同——先检查现有凭证，无效时执行刷新脚本。

凭证有效性检测

CC 使用与 Vertex AI SDK 相同的认证链（google-auth-library 的 Application Default Credentials）检测 GCP 凭证是否有效。

超时保护： 5 秒超时，防止本地无 GCP 环境时元数据服务器挂起 12 秒。

与 Vertex AI 的关系

Vertex AI 直接使用 ADC（Application Default Credentials），gcpAuthRefresh 负责在凭证过期前刷新。

企业托管认证

isManagedOAuthContext()

托管上下文的特殊行为：

  • 忽略本地 settings.json 中的 apiKeyHelper
  • 忽略终端环境变量 ANTHROPIC_API_KEY
  • 只接受通过管道（env/FD）注入的 Token

原理： 防止终端 1 里 export ANTHROPIC_API_KEY=sk-xxx 影响到 CCR 远程会话。
