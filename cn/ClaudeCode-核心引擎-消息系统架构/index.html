消息系统架构

概述

utils/messages.ts（5512 行）是消息系统的核心，定义了 Claude Code 内部消息格式与 Anthropic API 消息格式之间的完整映射关系。这个系统解决了一个根本性问题：UI 展示需要的消息 ≠ API 需要的消息。

两套消息格式

内部格式（Message）— 面向 UI 和状态管理

API 格式（MessageParam）— 面向 Anthropic API

normalizeMessagesForAPI() 负责把内部格式转换为 API 格式。

各消息类型详解

UserMessage

isMeta 的典型用例：

  • 工具调用结果（tool_result content）
  • 系统注入的 <system-reminder> 提醒
  • 待处理通知（<task_notification>）

isMeta=true 的消息在 UI 里不展示，但会发给 API。

SystemMessage

大多数 SystemMessage 仅用于 UI 展示，不发给 API。除了：

  • SystemLocalCommandMessage（本地命令输出）：会被转换为 UserMessage 发给 API

AttachmentMessage

Attachment 是一个 discriminated union，包含：

attachment.type 用途
agent_listing_delta Agent 列表更新（防止 cache miss）
mcp_instructions_delta MCP 服务器指令
nested_memory 嵌套 CLAUDE.md 注入
deferred_tools_delta 延迟加载工具声明
companion_intro Buddy 吉祥物介绍
skill_discovery 相关 Skill 推荐
git_file Git 文件追踪

AttachmentMessage 在发给 API 时会被合并到相邻的 UserMessage 内容中（reorderAttachmentsForAPI()）。

TombstoneMessage

TombstoneMessage 是"消息被删除了"的标记。在 normalizeMessages 时，遇到 tombstone 就删除对应的目标消息，tombstone 本身也不发给 API。

函数 用途

消息 ID 系统

每条消息有 UUID，用于：

  • TombstoneMessage 定位目标
  • ProgressMessage 关联 tool_use
  • fileHistory 快照按消息 UUID 分组
  • commit 归因追踪哪条消息触发了哪次文件修改
